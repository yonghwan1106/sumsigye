# 숨시계 | 정전 골든타임 AI

숨시계 | 정전 골든타임 AI — 2026 AI 라이프 솔루션 챌린지 아이디어 후보작 「12번. 전력안심망 AI」(제안자 아이디어)를 이번 대회를 위해 새로 구현한 시제품입니다. 가구·기기 상태·비상전원은 합성 데이터이고, 재난문자는 행정안전부 재난안전데이터공유플랫폼 실제 공공 데이터, 기상은 Open-Meteo 재분석 자료(CC BY 4.0)입니다. 전력 사용 패턴(AMI) 분석은 쓰지 않습니다.

- 시제품: **https://sumsigye.vercel.app**
- 정전 때 지자체 담당자가 인공호흡기·산소발생기를 쓰는 집에 비상전원을 보낼 순서를 정하도록 돕습니다. AI는 재난문자를 읽고 설명 문장을 쓰며, 순위·배정·시간 계산은 코드가 하고, 배정은 담당자가 한 집씩 승인해야 확정됩니다.
- 기존 저장소를 복사하지 않고 이 대회를 위해 새로 작성했습니다.

## 실행

```bash
npm install
npm run dev -- -p 3102      # http://localhost:3102
npm test                    # vitest (L1·L3·엔진·생존함수·API·채점)
npm run typecheck
npm run build
```

- AI 키는 **환경변수로만** 넣습니다(`ANTHROPIC_API_KEY`). `.env.local`이나 다른 파일에 쓰지 않습니다. 오프라인 스크립트는 `node scripts/with-key.mjs --key-file <키 파일> -- <명령>`으로 돌리면 키를 파일에서 읽어 자식 프로세스 환경변수로만 넘깁니다.
- 키가 없으면 **데모 모드**로 동작합니다(`/api/health` → `"mode":"demo"`): 재난문자 읽기는 사전계산 결과 또는 규칙 추출기, 운영자 메모·행동지침은 사전계산 또는 고정 템플릿.
- 운영 배포는 `vercel --prod -e ANTHROPIC_API_KEY=… -e ANTHROPIC_MODEL=claude-haiku-5-5 -e ANTHROPIC_FALLBACK_MODEL=claude-haiku-4-5 -e AI_DAILY_CAP=300 -e AI_RPM_PER_IP=6`처럼 배포 명령에 키를 붙입니다(값은 명령 문자열에 직접 쓰지 않고 같은 셸 호출 안에서 파일로 읽은 변수로). **`-e` 값은 그 배포에만 붙으므로 재배포할 때마다 다시 넣어야 합니다.** Git 자동배포는 끊어 두었습니다(자동배포 때 키가 빠지기 때문).
- AI 호출 상한: IP당 1분 6회 · 인스턴스당 하루 300회(서울 자정 초기화) · 입력 1,000자. 실시간 모델 `claude-haiku-5-5`, 실패 시 `claude-haiku-4-5` 1회, 그래도 실패하면 규칙·템플릿.

## 평가 요약 (값은 `data/eval/*.json`, 2026-10-25 20:00 동결)

**정답 라벨 검수 전 — 규칙 추출기 대비 일치율.** 정답 라벨은 AI가 만들지 않습니다. 규칙을 만들기 전에 골드 60건을 따로 떼어 두었고(커밋 `E1-A2: split` < `E1-A3: freeze rule extractor r1`), 동결한 규칙 추출기 출력으로 초벌한 검수 시트(`data/review/`)를 응모자가 원문을 보며 검수합니다. 지금은 응모자 검수 전(0/60)이라 정답 대비 정확도는 싣지 않았습니다.

1. **재난문자 읽기** (`l1_results.json`, 개발용 문자에서 규칙 r1 출력과 견준 일치율 — 정확도가 아님)
   - claude-sonnet-5(270건): 시각 일치 93.7%(190칸) · 값 없음 일치 98.9% · 관련 문자 F1 0.979 · 원인 6분류 일치 91.3%
   - claude-haiku-5-5(고정 문자 12건): 시각 일치 100%(13칸) · 종류 일치 83.3%
   - 자동 검증: 근거 문구가 원문에 그대로 있는 비율 규칙 100% · haiku-5-5 97.6% · sonnet-5 99.4%
2. **복구시간 분포** (`l2_results.json`, 사건마다 그 사건을 뺀 모형으로 시험)
   - 선택 모형 M0(로그정규, 원인·야간 구분 없음). 야간 χ²=2.541 p=0.111 · 원인군 χ²=4.044 p=0.257 → 원인별 차이는 표본이 작아 확인하지 못했습니다.
   - 발생·복구 확인 12건: '10번 중 8번' 범위에 실제 복구가 든 사건 M0 12/12(95% 구간 75.8~100%), 관측 경험분위 9/12. 복구 시각 없는 14건: 범위 안 14 · 벗어남 0.
   - pinball 평균은 고정 2시간(26분)·경험분위(23분)가 M0(33분)보다 낮습니다. M0은 범위를 넓게 잡아 적중을 지키는 대신 점 예측은 더 무딥니다.
3. **비상전원 배정** (`l4_results.json`, 합성 시나리오 400개, 부트스트랩 2,000회 95% 구간)
   - 기기 멈춤 가구 평균: 단순하게 보내면(R1) 5.213곳 [4.625, 5.825] → 숨시계 4.838곳 [4.322, 5.395]. 같은 시나리오 짝 차이 R1 − 숨시계: 광역 0.76곳 [0.51, 1.02] · 소규모 −0.01곳 [−0.09, 0.07] · 전체 0.375곳 [0.243, 0.513].
   - **불리한 결과도 그대로 싣습니다**: 복구시간을 「고정 2시간」으로 가정한 같은 배정기(A1)가 4.675곳으로 숨시계보다 적었습니다(A1 − 숨시계 전체 −0.162곳 [−0.22, −0.107]). 배정기가 쓰는 복구시간 모형은 진행 중 사건 111건까지 써서 채점에 쓰는 26건(확인·구간 사건)보다 복구를 길게 봅니다.
   - 실제 복구시간을 아는 경우(오라클) 4.493곳. 호환 위반: 숨시계·R1 0건.
   - AI 챗봇에게만 맡기면(같은 30개, 프롬프트 `prompts/llm_alloc_baseline.md`, 출력 상한 2,000토큰): claude-haiku-5-5 5.733곳 · 호환 위반 합 91 / claude-sonnet-5 6.033곳 · 호환 위반 합 0 · 응답 실패 17/30(출력 상한 안에 배정 JSON을 끝내지 못함 → 전부 미배정으로 채점). 같은 30개에서 숨시계 4.867곳 · R1 5.2곳. 응답에 성공한 시나리오만 놓고 보면(sonnet-5 13개, `llm.ok_only`) sonnet-5 2.231곳 · 숨시계 2.231곳 · R1 2.462곳 — 차이가 없습니다.
   - 해석: 단순하게 보내면보다 나은 부분은 광역 시나리오에서만 나오고, 그 몫은 복구시간 모형이 아니라 호환·잔량·도착을 함께 푸는 배정 계산에서 나옵니다(A1이 더 적음). 사전식(멈춤 가구 수 먼저)이라 멈춤 시간 평균은 숨시계 332분이 R1 250분보다 깁니다.
   - 민감도 12행(`l4_sensitivity.json`) 모두에서 R1 − 숨시계 95% 구간이 0보다 큼.

## 응모자 검수가 오면 (한 줄로 다시 만들기)

1. 검수한 CSV 3개(`data/review/gold_review.csv` · `link_review.csv` · `events_review.csv`)를 같은 이름으로 둔다.
2. `npm run data:ingest-review` → 커밋 `E1-A9: gold labels reviewed by applicant (g=NN)`.
3. (키) `node scripts/with-key.mjs --key-file <키> -- npm run data:llm -- --model claude-haiku-5-5 --split gold,fixtures` · `... --model claude-sonnet-5 --split gold` → 커밋 `E1-A9b`.
4. `npm run rebuild:data` — 사건표·복구시간 모형·재난문자 평가·시나리오·배정 평가를 다시 만든다. 화면 문구는 `l1_results.json`의 `meta.reviewed_n`에 따라 「응모자 검수 g건」으로 자동으로 바뀐다(정확도 표는 g ≥ 40일 때).
5. 모형 값이 바뀌었으면 `data/eval/llm_baseline_runs.json`을 지우고 `npm run eval:llm-baseline`(키, 60회) → `npm run eval:alloc -- --merge-llm`, 메모는 `npm run build:scenarios -- --llm`(키) — 키 없이 돌리면 바뀐 상태의 메모가 템플릿으로 떨어진다. 그다음 키를 넣어 다시 배포.

자세한 단계는 `pipeline/README.md`.

## 한계

1. 가구·기기 상태·비상전원은 합성 데이터입니다. 배정 효과 수치는 합성 시나리오에서 잰 값이며 실제 현장 성능이 아닙니다.
2. 복구시간 분포는 재난문자가 발송된 정전만으로 추정했습니다. 짧은 정전과 문자 없는 정전(예: 2026-07-29 독산동)은 빠져 있고, 복구 안내를 생략한 정전이 더 짧을 수 있어 편향이 남습니다. 한전 실시간 예측값이 아닌 가정·범위값입니다.
3. 휴대용 산소발생기·석션기·기침유발기의 배터리 값과 이동 속도·출동 준비 시간은 가정값입니다.
4. 복구시간 모형과 배정 평가의 복구시간은 같은 재난문자 자료에서 나왔습니다. 평가에서는 뽑힌 사건을 뺀 모형으로 배정해 같은 사건으로 채점하지 않았습니다.
